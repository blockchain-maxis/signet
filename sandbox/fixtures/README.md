# Sandbox Fixture Contracts

This directory contains purpose-built Soroban contracts and their pre-compiled WASM binaries used by the contract simulator and sandbox tests (Backlog ID `F-09`).

The WASMs are committed under [`wasm/`](./wasm) so host tests run without requiring the WASM build toolchain. A CI parity job verifies that the committed WASMs match a fresh build from source.

The last column names every Rust and Go test that uses the fixture, under the file the test is in. `node sandbox/fixtures/check-readme.mjs` checks each of those names against the code, and the sandbox CI job runs it, so the column cannot drift back into names that do not exist.

Reading it:

- Most tests in `simulate.rs` are written once as a plain `fn name(lane: u32)` and run on every protocol lane through the `#[test] fn name()` wrappers that `on_lane!` generates. `cargo test name` runs each lane's copy.
- A test is listed where it uses the fixture, even when a helper installs it. `counter_v1` is installed by `ab_with` in `simulate.rs`, as the `A` side of every A/B diff, and by `session` in `cli/internal/dev/reload_test.go`, so tests that never name it are listed against it. `looper` and `hog` are installed together by `guarded`, and `dice` by `seeded`.
- `TestRecordUICycleFixtures` is skipped unless it is asked to record. It writes the recorded cycles in `apps/sandbox-ui/src/fixtures/cycles/`, which `cli/internal/dev/render_test.go` reads. That file is not listed: it uses the recordings, named after these fixtures, and never loads a WASM.

## Rebuilding

Run the build script from anywhere in the repository:

```bash
sandbox/fixtures/build.sh
```

Acceptance parity check:

```bash
sandbox/fixtures/build.sh && git diff --exit-code sandbox/fixtures/wasm
```
