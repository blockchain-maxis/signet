## Problem
Newly linked wallets from the CLI are not picked up by the indexer promptly, meaning their deploy activities aren't shown and the "indexing..." badge doesn't appear in the dashboard.

## Root cause
The CLI pairing completion path in `completePairing` manually writes a `Wallet` row without setting `indexRequestedAt`, unlike the dashboard's `linkDeployWallet` which explicitly requests an indexer scan upon linking.

## Fix
Refactored `completePairing` to reuse `linkDeployWallet` inside the transaction, inheriting its exact creation and conflict semantics, including setting `indexRequestedAt`. The `CompleteResult` was updated to return a `LinkedWallet`, and the `indexingPending` flag is now bubbled up through the API (`/api/cli/pair/complete`) to the CLI command output (`Result`).

## Testing
- Ensured `pairing.test.ts` passes with the updated `LinkedWallet` payload structure.
- Updated `claim-link-profile.spec.ts` to assert that `indexingPending` is returned and `indexRequestedAt` is populated in the database.
- Modified the Go CLI (`pair.go`, `flow.go`, `flow_test.go`) to decode the new `indexingPending` field and map it into the JSON output.
